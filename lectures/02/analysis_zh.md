# 第 02 讲作业：结果中文导读

正式报告是同目录下的 [answer.md](answer.md)。它分成原版 FAQ 课堂练习和 Advanced 术语表作业两个部分。本页用于帮助理解实验与报告。

## 我们实际完成了什么

从课程的 `data/glossary.json` 读取 58 个术语，用课程脚本生成 116 条问答；把定义包装成带 `answer` 与 `needs_review` 的 JSON，再添加 8 条词表未收录术语的训练例。最终训练集 124 条、验证集 12 条、测试集 18 条。

你在 Colab 里实际运行了模型加载、训练前评测、3 轮 LoRA 训练、训练后评测和结果导出。代码、数据准备、评分设计与下面的回答分析由 Codex 协助。

## 三种方法的结果

| 方法 | 作答方式 | 自动内容评分 |
|---|---|---:|
| 原始模型 | 闭卷回答，没有提供术语定义 | 5/18 |
| 微调后模型 | 学过训练数据后，仍闭卷回答 | 7/18 |
| 简单查词 | 在术语表中按名称或别名查找，返回原定义 | 15/18 |

三种方法的 JSON 格式均为 18/18 通过。自动内容分数净增加 2 题，其中 4 题改善、2 题退步。训练用了 205.98 秒，完成 48 次参数更新；日志中的 loss 从约 2.40 降至 0.36。

这里的“内容评分”使用关键词和复核标记，因此需要结合原始回答理解。

## 三个代表性回答，直接看判断依据

### Epoch：确实有改善

词表把 epoch 定义为完整遍历训练数据集一次。模型训练前把它解释为一般的时间段；训练后解释为“用于更新模型权重的整个数据集的一次遍历”，并提到过多轮次可能过拟合。这条训练后回答与词表的核心含义一致。

### LoRA：自动通过仍然可能答错

词表写的是冻结预训练基础模型权重，训练新增的低秩矩阵。模型却说低秩矩阵被冻结，把关键对象说反了。自动规则只检测到了 fixed、low-rank、matrices 一类词，因此没有发现句子关系错误。

所以报告把这条记为关键词评分漏检的概念错误，而不是把自动通过直接当成事实正确。

### DPO：本次任务考察词表覆盖范围

DPO 不在这份课程词表的条目里。实验规则要求对未收录术语返回 `needs_review=true`，请求复核。模型训练前后都直接给出解释，并标为 false，因此违反了这项任务规则。

“词表未收录”与“现实中没有这个概念”是不同的问题。即使模型拥有外部知识，本次实验也要求它按课程词表的覆盖范围行动。6 道未收录题训练后都未正确请求复核，这是本次结果中一个明确的限制。

## 查词程序为什么也会错

它靠术语名和别名匹配。Token 的改写题提到了 API 费用，程序抓住 API，返回了 API 的定义。Learning rate 和 Epoch 的改写题没有直接出现术语名，程序就误以为没有条目。

这说明简单查词虽然能准确返回已有定义，也会受到问题表达方式的影响。本次没有测试语义检索或完整 RAG 系统。

## 报告的结论

本次短时微调在部分术语回答上有所改善，但对未知范围的判断没有改善，回答中也仍有概念错误和无依据的补充。loss 降低只能说明训练目标下的预测表现发生变化，实际答题质量还需要单独评测。

对于需要来源、经常更新的术语定义，检索词表更方便维护和核对；微调适合尝试学习固定格式或重复任务行为，但实际效果需要验证。
